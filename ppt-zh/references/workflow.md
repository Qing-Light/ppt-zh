# 制作清单与异常处理

## 统一清单

每次任务在工作目录建立 manifest.json（UTF-8 JSON），不写入技能目录。制作过程中更新同一份记录，PPT、溯源和验收共用它。以下为字段示例，实际内容必须来自输入；未知字段用 null 并说明，不复制示例值冒充事实。

```json
{
  "schema_version": 1,
  "layout_config_version": 4,
  "actual_fonts": [],
  "layout_overrides": [],
  "inputs": [{"path": "paper.pdf", "type": "pdf", "role": "primary", "readable": true}],
  "paper": {"title": "论文标题", "authors": ["作者"], "affiliations": ["单位"]},
  "figures": [{"id": "Fig.1", "source": "paper.pdf 第3页", "caption": "原文图注", "panels": ["a", "b"], "asset": "fig1.png", "crop": null}],
  "pages": [{"page": 1, "role": "cover", "claim": "论文身份信息"}],
  "blocks": [{"id": "B1", "page": 3, "source": "paper.pdf 第2页 Introduction", "evidence": "必要原文", "draft": "草稿", "humanized": "编辑输出", "final": "上屏终稿"}],
  "exceptions": [],
  "review": {"science": "pending", "visual": "pending"}
}
```

清单必须包含全部 Figure、全部 N+5 页和全部正文块。背景 B1–B3；技术路线 R1–R4 至 R1–R6 和目标 G；结论 F1–FN；不足 L1–L3。页角色为 cover、outline、background、methods、result、limitations。结果页另记 figure_id；图号顺序以正文核实结果为准。

`humanized` 表示学术文案检查后的文本，不要求与 `draft` 不同。每块另记 `edit_status`（`unchanged` 或 `modified`）及 `edit_reason`；无须修改时写「已检查，无需修改」。这些状态由执行者如实记录，结构脚本不能证明实际执行了语义核对。

源位置使用 PDF 页码，或 DOCX 章节/段落定位与本次渲染页码；DOCX 页码随渲染环境变化，不单独作为唯一定位。不得通过改写清单来掩盖实际 PPT 的缺项。

## 对象命名

使用生成工具支持的形状名称（PPTX cNvPr name），不把名称显示在幻灯片上：正文对象为 `block:B1`、`block:F1` 等；封面为 `presenter` 和 `date`；结果页图片为 `figure:Fig.1` 等。一个正文块对应一个文本框；技术路线 R 块允许共同存在于名为 `methods-table` 的原生表格中。图内 panel 可以分开插入，图片名称以 `figure:Fig.1:` 开头。

## 核对和异常处理

异常按以下结果处理：可可靠恢复则继续并记录；仅影响局部则完成其余部分、保留待确认项；缺失关键证据或渲染能力则标记未完成。`exceptions` 中逐项记录 `type`、`affected_pages`、`evidence`、`action`、`status`（resolved/pending）和已有用户决定。不要对已有明确授权的例外重复询问。仍有影响科学准确性或可读性的 pending 项时不宣称最终验收通过。

- 文件损坏、加密或不支持的旧版 DOC：先尝试可用的只读读取/转换方式，保留源文件；失败时明确请求可读取的 PDF 或 DOCX，不把未读取部分当作空白。

- PDF、DOCX 都有时先核对版本。实质内容冲突时暂停受影响部分并询问采用哪个版本，不能拼成不存在的论文。
- 扫描 PDF 可 OCR 辅助提取，数字、公式、图注回看原页核对；无法读清的内容标为待确认。
- DOCX 原图像素不足时报告实际清晰度，请用户提供高清原图；提高导出 DPI 不等于增加原图细节。
- 外供 Figure 与正文不一致时，对照图号、panel、图例和数据确认；仅分辨率不同且内容一致可采用高清版并记录，实质差异须确定论文版本后再用，不能静默替换。
- 跨页 Figure 允许将同一 Figure 的完整部分拼接，记录页码与裁切区域；核对共享图例、重复部分和 panel 顺序。
- 图号不连续时先核查漏页和补充材料；N 按核实的正文主图数量计数，不按最大编号猜测。
- 区分阅读顺序和图号：F1–FN 是结果块的连续 ID，`figure_id` 保留真实图号。例如第三张正文图为 Fig.4 时，F3 对应 Fig.4，不将原图重命名为 Fig.3。Supplementary/Extended Data 不自动计入正文主图；无法从正文和图注确定时列出候选请用户确认。
- 超出4–8图仍保留全部正文主图与 N+5 结构，提示可能超出10–15分钟；不得自动删图。
- 长图注、密集 Figure 或长标题放不下时先调整框尺寸和同图 panel 布局。若仍无法满足完整性与可读性，记录冲突并请用户决定结构例外，不能缩到不可读或静默拆页。
- 不足不足三条时不凑数，记录缺口并请求用户决定是否允许减少条目。
- 读取、生成或渲染工具不可用时明确说明未完成阶段；不得用结构检查冒充实际打开、渲染或目检通过。

用户允许减少不足条目、拆页或改变总页数等结构例外时，记录实际要求；当前基础脚本仍按标准 N+5 和三个不足块检查。保留原始失败报告，将具体失败项列为经用户认可的例外并人工复核，其余失败仍需修复；不得修改输入清单或称脚本已通过。

## 冲突优先级

用户明确要求优先于默认版式；科学事实忠实和图片数据完整始终保留。布局冲突按数据完整性、坐标轴/图例/比例尺可读性、panel 关系与顺序、版式参数、美观偏好处理。推荐宽高比、空白率和禁止孤行等不得导致裁掉数据；放宽时记录具体原因和测量结果。N+5 或一图一页无法兼容可读性时，报告冲突，不自行改变结构。

## 验收分工

机器检查：ZIP/XML 可解析、页数、命名对象、原生文本存在、文本框边界、结果图与结论、正文块与溯源覆盖、交付文件存在。

逐页目检：实际换行、字体替换、文字溢出与遮挡、图注可读性、图片错切、panel 完整性。科学核验：数字、条件、比较对象、因果和证据来源。结构检查通过不能证明后两类通过。
