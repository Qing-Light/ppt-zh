# ppt-zh v2.0 · 论文组会 PPT

将用户提供的论文制成中文、可编辑的组会演示。先确定论文证据与主图，再写文案和排版。用户当前明确要求优先于本技能默认参数。

## 执行顺序与资源

1. 阅读 [workflow.md](references/workflow.md)，建立工作目录中的 `manifest.json`，完成输入核对、论文解析及页面规划。
2. 按下文内容规则写作，读取 [学术文案检查](references/humanizer-academic-ppt.md)；依据 [traceability-template.md](references/traceability-template.md) 从写作开始同步记录溯源。
3. 排版前读取 [layout.md](references/layout.md) 与 [版式参数配置](references/layout-tokens.json)，将配置用于生成工具，记录实际字体与参数覆盖，生成原生可编辑 PPTX。为内容对象设置稳定名称，见 workflow 的对象命名约定。
4. 渲染并逐页目检；运行 `python3 scripts/validate_pptx.py <PPTX路径> --manifest <清单路径> --trace <溯源路径> --preview <预览路径>`。脚本只做结构检查，不能代替视觉和科学核验。
5. 修复失败项后重新检查。按原有三个文件交付；清单和机器检查报告保留在工作目录，不额外强制交付。

## 输入与依赖

- 必需：论文源文件，支持 PDF 或 Word（`.docx`），至少提供一种。缺失时询问用户，不编造论文内容。
- DOCX 输入只把正文、表格、题注和内嵌图片作为论文材料，不把 Word 批注、修订说明或备注作为论文内容。同时提供 PDF 和 DOCX 时，可用 DOCX 提取文本，但以 PDF 核对正式版面、图号和科学内容。
- 可选：Fig.1–Fig.N 文件、仅供观察版式的参考 PPT、汇报人、汇报日期。
- 封面默认只显示「汇报人：」「汇报日期：」两个标签，冒号后留白，不填姓名、日期、XXX、YYYY.MM 或下划线。文件名日期仍可用 YYYY.MM 占位。两标签默认22pt，且不得大于该页红色中文标题的实际字号。
- N 只统计正文主图，排除补充图；核对图号与图注，无法确定 N 时询问。4–8 张为适用范围参考，不是删减主图的授权。
- 必须读取内置 [学术文案检查](references/humanizer-academic-ppt.md)，只针对学术描述检查并按需修改，不逐项执行全部31条通用模式。[humanizer 完整版](references/humanizer-zh.md) 保留供遇到具体表达疑难时参考，无须每次全文加载。这里的 `humanizer` 指执行这些编辑规范，不依赖独立安装、同名 API 或额外代理。学术检查文件缺失或无法读取时说明未完成，不伪造检查记录。
- 制作 PPTX 时读取当前环境提供的可编辑演示文稿制作技能，选择能生成原生文本框与表格的工具。使用其渲染检查能力；不得以整页图片代替可编辑演示稿。

## 内容与来源

1. 读取论文，记录标题、作者、单位、正文主图编号与来源位置（PDF 页码，或 DOCX 章节/标题及渲染页码），列出 N+5 页清单及每页主张。英文论文翻译标题；中文论文保留原题。
2. 科学图片只使用该论文正文主图；封面另使用论文首页标题、作者和单位区域。不得网络取图、AI 生图、重绘图表或根据文字/表格另造数据图。
3. 数字、单位、样本量、组名、图号与原文一致，不四舍五入、换算或补全；相关不改因果，「首次」「显著」仅在原文明确支持时使用。论文缩写首次给全称。
4. 允许裁切、等比缩放、在同一主图内重排完整 panel、添加中文标注。不跨图混拼，不把一张主图拆成多个结果页。保留字母、轴、图例、比例尺与显著性标记。
5. 从空白演示文稿新建。参考 PPT 仅用于观察版式，不另存为、不复制页面、母版、主题、图片、作者、数据或汇报人。

## 文案与内置 humanizer 流程

为以下每个学术描述块分别写准确草稿并标原文位置，再按学术文案检查核对，仅修改确有问题的表达，保存检查后的输出和上屏终稿：

- B1–B3：背景三段，顺序为大背景、已知、缺口，不提前写结果。
- R1–Rn 和 G：技术路线各行内容及目标句。默认 5 个研究阶段，按论文实际可用 4–6 个，不套用示例化学研究流程。
- F1–FN：每图先写 2–4 句草稿，单独 humanize，再仅通过删词和调序压为一句，不新增数字、判断、因果，保留必要条件与限定。无法忠实压缩时重写草稿并重新 humanize。
- L1–L3：证据边界、替代解释、不能证明。仅写论文提及或明确支持的内容；材料不足时说明缺口并询问，不为凑三点编造局限。

固定标签、表头、数字与原文图注不交给 humanizer。上屏正文必须来自对应检查输出；准确通顺的草稿允许原样保留，记录「已检查，无需修改」，不得为制造润色痕迹强改。每图结论采用「对象 + 结果 + 边界」，不以「本图表明」开头；恰好一句、一个句号，最多两行。

## 固定页面结构

总页数 N+5，不额外增加目录、过渡、总结或致谢页。

| 页面 | 内容 |
| --- | --- |
| P1 | 论文首页（PDF 或 DOCX 渲染页）截图或分块拼接，标题、作者、单位完整，无摘要；独立可编辑红色中文标题；独立汇报人和日期文本框 |
| P2 | 汇报安排：四行横向分区，独立蓝色方块编号01–04，右侧依次为研究背景、技术路线、结果讨论、不足与展望；蓝色标题、浅蓝细分隔线 |
| P3 | 背景三个编号点，24pt，正文统一黑色，不自动标红关键词 |
| P4 | 研究阶段 / 主要内容两列表格，默认 5 阶段，22pt 全部居中；下方 24pt 蓝色单行目标句 |
| P5–P(N+4) | 按 Fig.1–N 每页一张完整主图、一个小节标题、原文图注、底部一句结论 |
| P(N+5) | 不足三个编号点，24pt，正文统一黑色，不自动标红限定词 |

排版前必读 [references/layout.md](references/layout.md)，其中包含画布、颜色、坐标、封面截取和 panel 排版的具体参数。

所有新增标题、正文、图注、表格、标注和结论使用原生可编辑元素；论文本身的主图与首页截图可为位图，不把「可编辑」误解为允许重绘论文图。

默认关闭自动关键词标红，不自行挑选术语、数字或限定词作为红色重点。背景与不足正文统一黑色，结果结论整句蓝色；图内默认不新增红色强调。仅在用户明确指定强调内容时添加红色标注。封面中文标题保留红色；论文原图自带颜色保持原样。

## 检查与交付

- PDF 以至少 300 DPI 提取图片；DOCX 优先提取原始内嵌图片，只在无法直接提取时使用至少 300 DPI 的渲染页裁切。图形等比缩放，宽高比误差 <0.5%。若外供主图与论文源文件不一致，以论文核实，不静默替换。
- 按 1920×1080 渲染并逐页目检，修复溢出、重叠、错切、失真和不可读文字。图注 9–10pt 加粗，结论20pt整句蓝色，不自动句内标红，图注与结论间距0.05–0.06 in。
- 多 panel 重排后检查完整性、顺序、行宽、行高与空白率，将测量方法和结果记录于溯源文件的 layout 校验部分。参数无法同时满足时优先保护数据完整性，向用户说明具体冲突，不静默裁掉数据或声称通过。
- 核对 N+5 页、一图一句、封面无摘要且署名/日期可编辑；核对所有正文块都有 humanizer 记录。
- 核对封面标签后留白且字号不超过红色标题；提纲为四行01–04独立编号块，标题不再附加中文序号；标红词与相邻中文、标点间无因分色新增的空格。英文词间及数字与单位间原本必要的空格保留，不能全局删除空格。
- 若提供参考 PPT，对比两者 ppt/media 媒体哈希并追溯来源；相同媒体须核实是否确为直接从论文提取，确保没有复制参考文件素材，不能仅靠哈希宣称来源合格。
- 交付三个文件：`组会汇报_<第一作者>_<短标题>_<YYYY.MM>.pptx`、同名 `_预览.png`（全部页面缩略图总览）、同名 `_溯源.md`。
- 溯源文件逐块包含：块 ID、目标页、论文源位置（PDF 页码，或 DOCX 章节/标题及渲染页码）、图号/必要原文片段、草稿、humanizer 输出、上屏终稿。另记图片来源页与裁切区域、panel 重排映射、layout 校验和最终检查结果。没有记录视为未完成。
- 未实际渲染或未执行学术文案检查时明确说明未完成项，不把中间文件当成检查通过的最终稿。检查后原样保留不属于未完成。
